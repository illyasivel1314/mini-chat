## 2. 通用约定

### 2.1 基础地址与环境

| 项       | 值                                                  |
| :------- | :-------------------------------------------------- |
| 服务端口 | `8888`（`application.yaml` 中 `server.port`）       |
| 基础路径 | `http://<host>:8888`                                 |
| REST 前缀 | 所有 REST 接口统一以 `/api` 开头                    |
| WebSocket 端点 | `/ws`（SockJS）                              |
| 前端 baseURL | 生产环境为 `http://146.56.197.54:8888/api`     |

### 2.2 鉴权方式

采用 JWT 无状态鉴权，令牌在请求头中传递：

```
Authorization: Bearer <token>
```

- **普通用户令牌**：登录接口返回（`subject = userId`）。
- **管理员令牌**：后台登录接口返回（`subject = admin 用户名`）。
- **免鉴权接口**：`/api/auth/login`、`/api/auth/register`、`/api/file/upload`、`/api/admin/login`。
- **后台接口**：`/api/admin/**`（除 `/login`）走独立 `AdminAuthInterceptor` 鉴权。
- **令牌有效期**：1 天（`expiration_time: 86400000`），HS512 签名。
- **鉴权失败**：HTTP 401，响应体为纯文本 `Invalid or missing token`（非 JSON）。
- **WebSocket 鉴权**：STOMP CONNECT 帧头携带 `Authorization: Bearer <token>`。

### 2.3 统一响应结构

除 `CommonResult` 自身外，所有控制器返回值由 `GlobalResponseAdvice` 统一包装为：

```json
{ "code": 200, "message": "success", "data": <实际数据> }
```

| 字段    | 类型   | 说明                                      |
| :------ | :----- | :---------------------------------------- |
| code    | int    | `200` 成功；其余为业务错误码              |
| message | string | `success` 或错误提示                      |
| data    | object | 实际业务数据（下表出参均指 `data` 内容）  |

> 无返回值（`void`）的接口，`data` 为 `null`。

### 2.5 通用枚举

| 枚举 | 值 | 说明 |
| :--- | :--- | :--- |
| **ChatTypeEnum** 聊天类型 | 0 / 1 / 2 / 3 | 私聊 / 群聊 / 系统消息 / 自发会话（“我的文件”） |
| **ContentTypeEnum** 内容类型 | 0 / 1 / 2 / 3 | 文本 / 图片 / 文件 / 表情(GIF) |
| **PositionEnum** 岗位 | 0–5 | 负责人 / Java 开发 / 前端开发 / C 端开发 / 三方测试 / 内部测试 |
| **DutyEnum** 职责 | 0 / 1 / 2 | 项目负责人 / 开发员 / 测试员（任务协同权限依据） |
| **TicketTypeEnum** 单据类型 | 0 / 1 | 需求单 / bug 单 |
| **TicketStatusEnum** 单据状态 | 0 / 1 / 2 | 开发中 / 已完成 / 已取消 |
| **VersionStatusEnum** 版本状态 | 0 / 1 / 2 | 进行中 / 已关闭 / 已取消 |
| **FlowActionEnum** 流转动作 | 0 / 1 | 创建 / 转包 |

### 2.6 conversationId 生成规则（会话 ID）

前端据此识别消息归属会话，与后端 `ConversationService.resolveConversationId` 完全一致：

| 聊天类型 | conversationId 规则                                     |
| :------- | :------------------------------------------------------ |
| 群聊(1)  | 直接取 `groupId`（即 `receiverId`）                      |
| 私聊(0)  | 双方用户 ID 按字典序升序后 md5，前缀 `p`                 |
| 系统(2)  | `md5("system" + receiverId)`                             |
| 自发(3)  | `md5("self" + senderId)`                                 |

## 4. 详细接口说明

### 4.1 用户认证（`/api/auth`）

#### 4.1.1 用户登录

- **URL**：`POST /api/auth/login`
- **作用**：手机号 + MD5 密码登录，返回用户信息与 JWT token。
- **需求**：F01
- **鉴权**：无需 token。

**入参**（JSON body，`UserLoginRequest`）：

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| phone | string | 是 | 手机号（11 位，登录唯一标识） |
| password | string | 是 | 密码（前端已 MD5） |

**出参**（`UserLoginDto`）：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | string | 用户 ID（32 位 UUID） |
| phone | string | 手机号 |
| account | string | 工号 |
| name | string | 姓名 |
| pinyin | string | 姓名拼音（搜索用） |
| avatar | string | 头像 |
| position | int | 岗位（PositionEnum） |
| duty | int | 职责（DutyEnum） |
| positionDescription | string | 职位概述 |
| token | string | JWT 令牌 |

**错误**：`1001` 用户不存在、`1013` 账号已注销、`1004` 密码错误。

#### 4.1.2 用户注册

- **URL**：`POST /api/auth/register`
- **作用**：注册新用户并自动登录（返回用户信息与 token），全员自动成为好友。
- **需求**：F01
- **鉴权**：无需 token。

**入参**（JSON body，`UserRegisterRequest`）：

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| phone | string | 是 | 手机号，正则 `^1[3-9]\d{9}$`，全局唯一 |
| password | string | 是 | 密码（前端已 MD5，后端直接存 MD5 值） |
| name | string | 是 | 姓名，2–20 字符 |
| account | string | 否 | 工号，≤20 字符 |
| position | int | 是 | 岗位（PositionEnum 0–5） |
| duty | int | 是 | 职责（DutyEnum 0–2） |
| detail | string | 否 | 详细信息 |
| positionDescription | string | 否 | 职位概述（历史字段） |
| avatar | string | 否 | 头像 |

**出参**（`UserLoginDto`，注册成功即自动登录）：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | string | 用户 ID |
| phone | string | 手机号 |
| account | string | 工号 |
| name | string | 姓名 |
| pinyin | string | 拼音 |
| avatar | string | 头像 |
| position | int | 岗位 |
| duty | int | 职责 |
| positionDescription | string | 职位概述 |
| token | string | JWT 令牌 |

**错误**：`1007` 该手机号已注册、`1002` 参数校验失败。

#### 4.1.3 全员好友列表

- **URL**：`GET /api/auth/friend/list`
- **作用**：返回全部未删除用户（即全员好友）。
- **需求**：F02
- **鉴权**：需要 token。

**入参**：无。

**出参**：`List<UserFriendDto>`，字段：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | string | 用户 ID |
| avatar | string | 头像 |
| name | string | 姓名 |
| pinyin | string | 拼音 |
| account | string | 工号 |
| phone | string | 手机号 |
| position | int | 岗位 |
| duty | int | 职责 |
| positionDescription | string | 职位概述 |
| detail | string | 详细信息 |
| deleted | boolean | 逻辑删除标记（此接口恒为 false） |

#### 4.1.4 我加入的群聊列表

- **URL**：`GET /api/auth/group/list`

### 4.2 聊天（`/api/chat`）

#### 4.2.1 私聊历史消息

- **URL**：`GET /api/chat/private`
- **作用**：分页拉取当前用户与指定好友的私聊历史（倒序，前端上滚加载）。
- **需求**：F03
- **鉴权**：需要 token（当前用户取自 token）。

**入参**（Query）：

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| userId | string | 是 | 对方用户 ID |
| page | int | 否 | 页码（0 起，默认 0） |
| size | int | 否 | 每页条数（默认 20） |
| sort | string | 否 | 排序，默认 `timestamp,desc` |

**出参**：`Slice<ChatMessageDto>`（分页对象，`content` 为消息数组、`empty`/`last` 等分页字段）。`ChatMessageDto` 字段：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | string | 消息 ID |
| senderId | string | 发送者 ID |
| senderName | string | 发送者姓名 |
| senderAvatar | string | 发送者头像 |
| receiverId | string | 接收者 ID |
| conversationId | string | 会话 ID |
| chatType | int | 聊天类型 |
| contentType | int | 内容类型 |
| content | string | 消息内容（JSON Schema 字符串） |
| timestamp | long | 发送时间戳（毫秒） |
| isRead | boolean | 是否已读 |
| replyTo | string | 引用消息 ID |
| atUsers | string | @提及用户 ID 列表（JSON 数组字符串） |
| atAll | boolean | 是否 @所有人 |
| forwardFrom | string | 转发来源消息 ID |
| recalled | boolean | 是否撤回 |

#### 4.2.2 群聊历史消息

- **URL**：`GET /api/chat/group`
- **作用**：分页拉取指定群的群聊历史（倒序）。
- **需求**：F03

**入参**（Query）：

**出参**：`Slice<ChatMessageDto>`（结构同 4.2.1）。

#### 4.2.3 会话列表（好友 + 群）

- **URL**：`POST /api/chat/message/friend`
- **作用**：返回当前用户有聊天记录的所有会话（私聊好友 + 群聊），含最新一条消息与未读数，按最新时间倒序。
- **需求**：F03
- **鉴权**：需要 token。

**入参**：无（body 可为空 `{}`）。

**出参**：`List<ChatFriendDto>`，字段：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |

#### 4.2.4 标记私聊已读

- **URL**：`GET /api/chat/message/read?userId=xxx`
- **作用**：将当前用户与 `userId`（对方）之间对方发来的消息标记为已读，并清零该会话未读/@角标。

**入参**（Query）：

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| userId | string | 是 | 对方（发送方）用户 ID |

**出参**：无（`void`）。

#### 4.2.5 撤回消息

- **URL**：`POST /api/chat/message/recall?messageId=xxx`

- **需求**：F05
- **鉴权**：需要 token。

**入参**（Query）：

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |

**出参**：`ChatMessageDto`（`recalled = true` 的消息）。

### 4.3 文件上传（`/api/file`）

### 4.6 WebSocket / STOMP 实时通道

#### 4.6.1 建立连接

- **端点**：SockJS `http://<host>:8888/ws`
- **连接头**：`Authorization: Bearer <token>`（STOMP CONNECT 帧，`StompAuthChannelInterceptor` 解析后设置 Principal）。
- **需求**：F03/F11/F13。

#### 4.6.2 发送聊天消息

- **目的地**：`/app/chat.send`（应用前缀 `/app`）
- **作用**：发送私聊/群聊/自发消息，落库后按类型推送（私聊/群聊均走 `/user/queue/private`，前端按 conversationId 归属会话）。
- **需求**：F03

**入参**（STOMP 消息体，`SendMessageVo`）：

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| receiverId | string | 是 | 接收者 ID（好友 ID / 群 ID） |
| chatType | int | 是 | 聊天类型（0 私聊 / 1 群聊 / 3 自发） |
| contentType | int | 是 | 内容类型（0–3） |
| content | string | 是 | 消息内容（JSON 字符串，如 `{"content":"..."}`） |
| replyTo | string | 否 | 引用消息 ID |
| atUsers | string | 否 | @提及用户 ID 列表（JSON 数组字符串） |
| atAll | boolean | 否 | 是否 @所有人 |
| forwardFrom | string | 否 | 转发来源消息 ID |

**推送**（订阅方收到的消息体为 `ChatMessageDto`，结构见 4.2.1）：

| 目的地 | 说明 |
| :--- | :--- |
| `/user/queue/private` | 私聊（推送给接收者与发送者回显）、群聊（逐成员推送）、自发（仅回显本人） |
| `/queue/system` | 系统消息广播（前端按 `receiverId` 过滤出属于自己的） |
| `/queue/pong` | 心跳响应（见 4.6.4） |

#### 4.6.3 系统消息广播机制（F11）

系统消息由 `SystemNotifyService.notify(userId, text)` 产生：**落库**（`chatType=2` 系统消息，`content` 为 `{"content":"文本"}`，计入未读）+ **广播**到 `/queue/system`。触发场景与接收人：

| 事件 | 接收人 |
| :--- | :--- |
| 需求单 / bug 单创建 | 负责人 |
| 单据转包 | 新负责人 |
| 单据状态变更 | 创建者 |
| 版本关闭 / 取消 | 该版本下所有未完结单据负责人 |

前端收到 `/queue/system` 后，若 `receiverId == 当前用户 ID` 则弹提示并刷新会话列表。

#### 4.6.4 心跳

- **发送**：客户端定期发送到 `/app/chat.ping`（body 可为 `{"timestamp": ...}`）。
- **响应**：服务端 `@MessageMapping("/chat.ping")` 收到后，向发送者 `/queue/pong` 回 `pong`。
- **需求**：F13（连接保活）。

## 5. 已知差异与注意事项

> 本轮已修复的缺陷：注册自动登录（返回 token）、群列表查询（按群成员关系查询）、退群接口（改 `POST` 且用户 ID 取自 token）、群成员接口（返回成员列表而非人数）、STOMP 心跳处理器（`/app/chat.ping` → `/queue/pong`）、文件大小限制对齐 PRD（图片 ≤10MB / 文件 ≤50MB）。

以下为实现与 PRD 仍需留意的点（均为配置或约定，非缺陷）：

1. **文件访问地址**：`/api/file/upload` 返回的 URL 由 `spring.file.request-address` 拼接，dev/prod 配置不同（dev 为 `127.0.0.1:8080/files/`，prod 为 `146.56.197.54:8888/files/`），需按部署环境核对。
2. **统一响应 code 值**：成功统一为 `200`（`CommonResult.success` 写死 `200`），业务错误码见 2.4。
