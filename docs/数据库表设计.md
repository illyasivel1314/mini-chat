# 内部沟通协作平台 — 数据库表设计

> 依据 PRD《内部沟通协作平台》V1.0（2026-10-16），对现有 `mini-chat` 项目的数据库表进行完善。
> 目标数据库：**MySQL 8.x**（当前 `pom.xml` / `application-*.yaml` 实际使用 MySQL）。
> 建表脚本见 `db/schema.sql`。

---

## 1. 设计约定

| 约定 | 说明 |
| :--- | :--- |
| 主键 | `VARCHAR(32)`，应用层 `CommonUtil.generateUuid()` 生成（UUID 去横线） |
| 时间戳 | `BIGINT`，毫秒级，`CommonUtil.generateTimestamp()` 生成 |
| 逻辑删除 | `TINYINT(1)`，0=正常 / 1=删除（仅用户表；单据不可删除，误建走“已取消”） |
| 枚举落库 | `TINYINT` 存枚举的 `value`，含义见第 2 节 |
| 命名 | 表名统一 `*_table`，与现有 `user_table` 等保持一致 |
| 字符集/引擎 | `utf8mb4` / `InnoDB` |

## 4. 逐表说明

### 4.1 `user_table` — 用户表

PRD F01 注册字段 + F12 逻辑删除的完整落库：

| 字段 | 类型 | 说明 | PRD 对应 |
| :--- | :--- | :--- | :--- |
| id | VARCHAR(32) PK | 用户ID | — |
| phone | VARCHAR(11) UNIQUE | 手机号，登录唯一标识 | 手机号（正则 `^1[3-9]\d{9}$`，全局唯一） |
| password | VARCHAR(32) | 密码（前端 MD5 值，不加盐） | 密码 |
| name | VARCHAR(20) | 姓名 | 姓名 2-20 |
| account | VARCHAR(20) | 工号（可选） | 工号（≤20，无唯一约束） |
| pinyin | VARCHAR(64) | 姓名拼音（搜索） | —（现有搜索功能） |
| avatar | VARCHAR(255) | 头像 | 头像（默认头像） |
| position | TINYINT | 岗位 | 岗位枚举（6 值） |
| duty | TINYINT | 职责 | 职责枚举（3 值，权限依据） |
| detail | VARCHAR(500) | 详细信息 | 详细信息（自由文本） |
| position_description | VARCHAR(255) | 职位概述 | —（历史字段） |
| deleted | TINYINT(1) | 逻辑删除标记 | F12 删除账号 |
| create_time / update_time | BIGINT | 创建/更新时间 | — |

- 全员自动好友（F02）无需好友表：`user_table` 中 `deleted = 0` 的用户即全部好友。
- 已删除账号：`deleted = 1`，登录被拒、好友列表消失、历史消息按姓名快照展示（姓名快照由消息落库时的 `sender_name` 快照或按 `sender_id` 冗余展示，见 4.4 说明）。
- admin 账号配置在 `application.yml`，**不落本表**（与注册用户体系隔离，F12）。

### 4.2 `conversation_table` — 会话表

PRD F03 的 `sessionWindowId` 落地：

- `id` 即 `sessionWindowId`，后端据此查关联用户（`conversation_member_table`）并 STOMP 广播。
- 私聊按“用户对等”复用同一会话（双方任意设备/清缓存后仍同一会话，F03 验收标准）。
- “我的文件”自发会话、系统消息会话各占一类，均按用户各一。

### 4.3 `conversation_member_table` — 会话成员与已读位点表

PRD F03“打开会话即更新本视角已读位点（不做对方已读回执）”与 F05“@未读角标”的落地：

| 字段 | 说明 |
| :--- | :--- |
| conversation_id + user_id | 唯一键，定义“某用户在某会话” |
| last_read_time | 已读位点（时间戳），未读数 = 该会话中 `timestamp > last_read_time` 且非本人发送的消息数 |
| unread_count | 未读消息数（会话列表角标，可冗余更新或实时计算） |
| at_count | 未清除的 `[有人@我]` 计数（红色角标，点开会话后清除） |

### 4.4 `message_table` — 聊天消息表

在现有表基础上新增 PRD F05 能力字段：

| 字段 | 说明 | PRD 对应 |
| :--- | :--- | :--- |
| conversation_id | 会话ID（sessionWindowId） | F03 |
| sender_id / receiver_id | 发送/接收者 | F03 |
| chat_type | 0私聊/1群聊/2系统/3自发 | F03/F07 |
| content_type | 0文本/1图片/2文件/3GIF | F04 |
| content | JSON Schema 内容 | F04 |
| reply_to | 引用消息ID（深度 1 层） | F05 引用 |
| at_users | @提及用户ID列表（JSON） | F05 @提及 |
| at_all | 是否@所有人 | F05 @所有人 |
| forward_from | 转发来源消息ID（标记来自 XX） | F05 转发 |
| recalled / recall_time | 撤回标记与时间 | F05 撤回（2 分钟内） |
| is_read | 遗留字段（见下） | — |
| timestamp | 发送时间 | F03 |

> **关于“姓名快照”**：F02/F12 要求“历史消息显示原姓名快照”。消息已通过 `sender_id` 关联用户，删除账号时仅置 `deleted=1`、不物理删除用户行，故历史消息仍能通过 `sender_id` 关联出姓名；无需额外在消息表冗余姓名快照。若担心用户行被物理清理，可在消息层冗余 `sender_name`（本版不强制，交由研发按 F12 语义选择）。

> **关于 `is_read`（遗留字段）**：现有代码以 `message_table.is_read` 做私聊未读；该模型对群聊不成立（群消息应“按用户”未读）。正确模型为 `conversation_member_table` 的 `last_read_time/unread_count/at_count`。本版保留 `is_read` 以避免破坏现有 `MessageDao`/`MessageService`，**建议后续迁移并移除该字段**。

### 4.5 `chat_group_table` / `group_member_table` — 群组与成员

- `chat_group_table` 新增 `owner_id`（群主，初始=创建者，可转让，F06“不能删自己需先转让群主”）。
- `group_member_table` 增加唯一键 `(group_id, user_id)` 防重复加群。
- 退群/被移除 = 删除成员行；重新入群新建行，可见全部群历史（F06，内网互信不做可见性切割）。

### 4.6 `version_table` — 版本

F08：仅项目负责人可创建/编辑/关闭/取消/删除。字段覆盖“版本名称、描述、计划发布日期、状态、创建人、创建时间”。删除仅当版本下无单据时允许（物理删除），否则只能关闭/取消。

### 4.7 `requirement_table` / `bug_table` — 需求单 / bug 单

- 需求单（F09）：项目负责人、开发员可创建；`owner_id` 为当前负责人，仅负责人可编辑/转包/改状态。
- bug 单（F10）：所有角色可创建；`creator_id` 始终不变（创建者可编辑标题/明细/截图/重新指定负责人），`owner_id`（当前负责人）可填原因/方案/结果截图/状态。
- 两者共用“开发中/已完成/已取消”状态机；单据不可删除，误建走“已取消”。
- 转包 = 变更 `owner_id` + 写 `flow_record_table`（单实体模型，不产生新记录）。

### 4.8 `flow_record_table` — 流转记录

F09/F10“单实体 + 流转记录”：`创建 → 转包1 → 转包2 …`。

| 字段 | 说明 |
| :--- | :--- |
| ticket_type + ticket_id | 定位单据 |
| action | 0创建 / 1转包 |
| operator_id | 操作人 |
| from_user_id → to_user_id | 转出人 → 转入人（转包时；创建时 to_user_id=负责人） |
| remark | 备注（转包必填） |

## 5. 表关系

```
user_table (1) ──< conversation_member_table >── (1) conversation_table
      │                                              │ (type=1)
      │ (好友：全员自动，无需关系表)                    └── group_id ──> chat_group_table (1) ──< group_member_table >── user_table
      │
      └──(sender/creator/owner)──> message_table / version_table / requirement_table / bug_table

version_table (1) ──< requirement_table (1) ──< flow_record_table
                    └──< bug_table        (1) ──< flow_record_table   (ticket_type 区分)
```

---

## 6. 索引说明

- `message_table(conversation_id, timestamp)`：会话历史 50 条分页查询（< 500ms 目标）。
- `conversation_member_table(conversation_id, user_id)` 唯一：广播目标 + 已读位点定位。
- `user_table(phone)` 唯一：登录与查重。
- `flow_record_table(ticket_type, ticket_id)`：流转链查询。
- 单据表 `version_id/owner_id/creator_id`：版本详情、按负责人过滤。

## 8. 达梦（DM8）迁移提示（PRD 硬约束，本版按 MySQL 交付）

PRD 要求达梦数据库，当前代码实际使用 MySQL。若后续切换到达梦 8，数据访问层需适配：

- 自增/主键：本项目主键为应用层 UUID 字符串，**不受自增差异影响**。
- 分页：达梦用 `LIMIT ? OFFSET ?`（兼容模式）或 `ROWNUM`/`TOP`，JPA/Hibernate 需切换 `Dialect`（DM 方言）。
- 驱动：`DmJdbcDriver`，连接串 `jdbc:dm://host:port`。
- 字段类型：`TINYINT`/`BIGINT`/`TEXT`/`VARCHAR` 在达梦均有对应（`SMALLINT`/`BIGINT`/`CLOB`/`VARCHAR`），需按达梦方言映射。
