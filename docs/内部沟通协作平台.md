## 1. 需求概述

### 1.1 需求背景

**为什么做？**

- **沟通痛点：** 工作环境为内网，无手机、无聊天软件，日常沟通只能靠座机电话、面对面等原始方式，信息无法有效、快速传达。
- **协同痛点：** 项目组当前依赖 Excel 和口头同步跟踪版本进度、需求单和 bug 单状态，信息分散、更新滞后、责任不透明。
- **公司内网环境人员固定（≤50 人），具备接受轻量安全策略（无验证码注册、MD5 密码）的信任基础。**

### 1.2 需求目标

**做成什么？**
在一个单 jar 应用内，为内网团队提供即时聊天（核心）+ 任务协同（版本/需求单/bug 单）的一体化协作平台，消除座机/口头/Excel 的原始协作方式。成功指标：

1. **业务指标：** 上线 1 个月内覆盖 ≥90% 内部沟通场景（替代座机/口头传达）；
2. **性能指标：** 消息端到端推送延迟 <1s（同内网）；登录/页面首屏 <2s；
3. **质量门槛：** 核心链路（注册→发消息→收消息；建版本→建单→转包→完结）通过率 100% 方可发布；
4. **效率指标：** 任务状态更新滞后从天级 降到 实时。

### 1.3 需求范围

| 范围    | 说明                                                         |
| :------ | :----------------------------------------------------------- |
| 包含    | 聊天模块（注册登录、好友、私聊/群聊/系统消息/自发会话、消息全能）、任务协同模块（版本、需求单、bug单、转包流转、变更通知）、账号管理后台（admin） |
| 不包含  | 个人博客网页（整体二期）；合并转发、自定义表情上传、桌面声音提醒、禁用账号、自助重置密码、消息删除、单据删除、服务端缩略图、文件类型黑名单、统计看板、移动端适配 |
| MP 范围 | 即本 PRD 全部“包含”项（V1.0 即 MP）                          |

**技术硬约束（不可妥协）：**

- SpringBoot 2.x + Vue 3.2 + 达梦数据库；
- 禁止额外中间件：无 Redis、Nginx、MQ 等；
- 前端构建产物放入 Java 工程 `resources/static`，以单 jar 运行；
- 实时消息采用 STOMP（Spring 内置 WebSocket 支持），任务通知复用同一通道。

### 3.2 功能详细说明

#### F01 注册与登录

**功能描述：**
以手机号为唯一标识的注册与登录。无验证码、无邀请码（已确认接受该内网风险）。

**注册字段与校验：**

| 字段     | 类型   | 必填 | 校验规则                                                     |
| :------- | :----- | :--- | :----------------------------------------------------------- |
| 头像     | String | -    | 默认头像，本期不提供上传修改                                 |
| 姓名     | String | 是   | 2-20 字符                                                    |
| 手机号   | String | 是   | 标准 11 位手机号，正则 `^1[3-9]\d{9}$`；全局唯一             |
| 密码     | String | 是   | 明文 6-20 位，无复杂度强制；前端 MD5 后传输，后端直接存 MD5 值（不加盐） |
| 工号     | String | 否   | ≤20 字符，仅格式校验，不做唯一性约束                         |
| 岗位     | Enum   | 是   | 负责人 / Java 开发 / 前端开发 / C 端开发 / 三方测试 / 内部测试 |
| 职责     | Enum   | 是   | 项目负责人 / 开发员 / 测试员（任务协同权限依据）             |
| 详细信息 | String | 否   | 自由文本                                                     |

**业务流程：**

1. **注册：** 填写表单 → 前端校验 → 提交（密码 MD5、手机号明文） → 手机号查重→入库→自动登录进聊天页→全员好友列表自动出现该新用户
2. **登录：** 手机号 + MD5(明文密码) → 校验 → 建立 session（同域共享给任务页/后台入口跳转）
3. **重复注册同一手机号：** 报错“该手机号已注册”，提示联系管理员重置密码
4. **记住密码：** 不做自研功能，依赖 Chrome 浏览器自带密码记忆

**边界条件：**

- 手机号格式非法 / 已注册 / 必填缺失：表单级错误提示，不落库；
- 密码错误：统一提示“手机号或密码错误（不区分，降低探测）；
- 已逻辑删除账号：无法登录，提示联系管理员。

**验收标准：**

- 新用户注册成功后，所有存量用户好友列表自动出现该用户，无需任何添加操作

- 注册/登录/改密全链路密码均以前端 MD5 值传输与比对，数据库存储值即前端 MD5 值

- 未登录访问任意页面/接口被重定向登录页或返回 401


#### F02 好友列表

**功能描述：**
全员自动好友（规模 ≤50 人），无添加/删除好友能力。

**交互布局：**

- 头像单独一列；其余列中 姓名 + 工号 合并一行、“岗位”单独一行；
- 顶部搜索框：按姓名/工号过滤；
- 点击好友 → 右侧面板显示该好友全部信息（姓名、手机号、工号、岗位、职责、详细信息）。

**边界条件：**

- 已逻辑删除好友：从所有人列表消失，历史消息显示原姓名快照；
- 无搜索结果：显示空态提示。

**验收标准：**

- 好友列表按约定两列布局渲染，点击展示详情

- 列表中不存在任何删除/添加好友入口


#### F03 会话与消息收发（核心）

**功能描述：**
消息列表包含群聊、私聊、系统消息、“我的文件”。每个会话有唯一 conversationId（会话 ID，前端据此识别消息归属会话）。群聊消息不再使用广播：后端先获取会话内全部成员，再以私聊方式逐人推送（`/user/{id}/queue/private`），前端收到后按 conversationId 归属会话；私聊消息同样走该通道。消息内容采用 JSON Schema 打包内容与样式（字段定义移交研发），GIF 消息必须含 emojiKey = 分组/文件名。

**业务流程：**

1. 打开会话 → 拉取最近 50 条消息 → 向上滚动按 50 条/页分页加载
2. 发送消息 → 后端落库（返回消息 ID）→ 私聊消息直接推送给对方；群聊消息先查询群成员，再逐人私聊推送（`/user/{id}/queue/private`）
3. 前端收到推送后按 conversationId 识别消息归属会话；会话列表同步刷新最新消息与未读角标
4. 用户离线期间消息持久化；重新登录后按会话补拉未读，会话列表显示未读角标
5. 打开会话即更新本视角已读位点（不做对方已读回执）

**边界条件：**

- 断线：自动重连（间隔 3s，不设次数上限），顶部黄色横幅“连接已断开，正在重连”；
- 离线期间禁止发送（输入框置灰提示），恢复后解除；
- 消息、聊天记录永久保留，不清理；
- 系统消息（任务通知等）同样支持离线补拉与未读角标。

**验收标准：**

- A 向 B 发送文本消息，B 在线时 1s 内收到；B 离线时重新登录后补拉并显示未读数

- 同一私聊双方在任何设备/清缓存后仍复用同一会话（按用户对等）

- 会话消息按 50 条分页正确向上加载，无重复无丢失


#### F04 消息类型

| 类型     | 规则                                                         |
| :------- | :----------------------------------------------------------- |
| 文本     | ≤5000 字符；emoji 表情可内嵌于文本消息一起传输；文本放置于气泡中。 |
| GIF 表情 | 必须单独成一条消息；素材打包在前端静态资源，按文件夹分组、按文件名匹配；消息 Schema存emojiKey=分组/文件名，前端渲染/static/emojis/{group}/{name}.gif；素材清单留设计/研发补充。GIF表情不设置气泡。 |
| 图片     | 单张 ≤10MB；存原图，前端 CSS 限制显示尺寸，不做服务端缩略图；图片不设置气泡。 |
| 文件     | 单个 ≤50MB；无类型黑名单（内部环境人员固定）；文件不设置气泡。 |

**存储：** 上传文件存 jar 外部配置目录（如 `/data/uploads`），按日期分目录；永久保留，运维手动归档清理。

**上传时序模型（已确认：方案 A -- 上传成功后才创建消息）：**

1. 点发送 → 文件以“本地消息”进入发送者聊天窗口（仅本人可见、前端内存态、临时占位）
2. → 气泡内实时显示上传进度条（0-100%，axios onUploadProgress）
3. → 上传成功 → 调用发送接口落库 → STOMP 广播 → 本地临时 ID 替换服务端消息ID
4. → 上传失败 → 消息保留为红色失败态（ ❗ 上传失败 / 重试 / 删除），消息始终未落库

- 他人可见性：文件/图片传输过程中及最终失败时，其他成员完全不可见该消息（无半截消息、零感知）；
- 进度显示：文件消息与图片消息统一显示实时进度条；文本/GIF 无上传过程不涉及；

**边界条件：**

- 失败后操作：发送者可在原消息重试（复用已选文件重新上传，不产生新消息）或 删除（仅清除本地态）；
- 页面刷新：未落库的本地态消息丢失，无残留；
- 断线场景：断线瞬间上传失败走同一失败态；配合 F13 离线禁发，重连后可点重试；不做断线续传与本地排队补传（本期明确不做）。

**验收标准：**

- 四种消息类型均能发送、推送、持久化、离线补拉后正确渲染

- GIF 消息按 emojiKey 正确渲染对应静态资源；单独成消息，不与文本混排

- 超限制文件在客户端即被拦截；断点上传失败有明确报错与重传入口

- 上传过程中发送者气泡实时显示进度且其他成员查询/推送均收不到该消息；上传失败后其他成员仍查不到该消息，发送者出现可重试的失败气泡

#### F05 消息能力（@/引用/撤回/转发）

| 能力    | 规则                                                         |
| :------ | :----------------------------------------------------------- |
| @提及   | 输入 @ 弹出群成员过滤下拉选择；被 @消息在未打开时于会话列表显示“[有人@我]”红色角标，点开会话后清除；点击角标/@可跳转到该消息并且该行高亮 |
| @所有人 | 所有成员均可使用，无限制                                     |
| 引用    | 任意消息可引用；引用深度仅 1 层；点击引用块滚动定位到原消息并高亮；原消息已撤回则显示“该消息已撤回”占位 |
| 撤回    | 仅限本人消息、发送后 2 分钟内；撤回后显示“你撤回了一条消息”类占位（保留引用锚点）；磁盘文件不删除 |
| 转发    | 单条转发，选择目标会话（联系人/群）；合并转发二期            |

**验收标准：**

- @后未读用户收到红色角标，点开后清除；点击跳转定位准确

- 超过 2 分钟的消息无撤回入口；撤回后占位、引用锚点行为符合定义

- 单条转发到联系人/群均成功，转发消息标记来自 XX

#### F06 群聊

**业务流程：**

1. 任意用户可创建群（无审批）：填群名（≤30 字符）→ 选择成员 → 创建；创建者自动为群主
2. 群主：改名、增加/移除成员（移除弹确认框）；不能删自己，需先转让群主
3. 成员：可主动退群；可在本地删除会话记录（不影响服务端）
4. 退群/被移除后重新入群：可见全部群历史（内网互信，不做可见性切割）
5. 限额：单用户创建群 ≤50 个；单群成员 ≤200 人

**边界条件：**

- 超出限额：报错提示；
- 群主删除自己：禁止并提示先转让；
- 群内撤回/转发/引用规则与私聊完全一致。

**验收标准：**

- 群主增删成员、改名实时同步所有在线成员

- 被移除成员收到确认交互后即时失去会话入口，重新入群可见全部历史

#### F07 “我的文件”自发会话

**功能描述：** 每用户一个固定自会话，用于给自己发文本/文件/图片（自存文件、跨机传输）。

**验收标准：**

- 每个账号自动存在“我的文件”会话，不可删除会话本身，收发正常

#### F08 版本管理（任务协同根节点）

**功能描述：** 版本是需求单/bug 单的根节点，仅项目负责人可创建/编辑/关闭/取消/删除。字段：版本名称（必填）、描述、计划发布日期、状态（进行中/已关闭/已取消）、创建人、创建时间。版本全员可见（透明星协前提）。

**状态级联规则：**

- 进行中 → （项目负责人操作）→ 已关闭：只读归档，禁止其下新建单据、禁止编辑存量单据
- 进行中 → （项目负责人操作）→ 已取消：其下未完结单据全部级联置为“已取消”
- 删除：仅当版本下无任何单据时允许（物理删除），否则只能关闭或取消

版本详情页 = 需求单列表 + bug 单列表两个页签；统计看板二期。
**通知：** 版本关闭/取消 → 系统消息通知该版本下所有未完结单据的负责人。

**验收标准：**

- 非项目负责人看不到创建/编辑/关闭/取消/删除入口，接口层同样拒绝

- 关闭版本后其下单据全部只读；取消版本后未完结单据级联取消并收到通知

- 有单据的版本删除入口被禁用

#### F09 需求单

**权限模型：** 项目负责人、开发员可创建；创建必填标题、需求内容、负责人（拥有者“概念统一为负责人”）；仅负责人可编辑内容、转包、修改状态。

**状态机：** 创建即开发中 → （负责人）已完成 / 已取消。已完成/已取消 → 只读（不可编辑、不可转包）。单据不可删除，误建走“已取消”。

**转包模型（单实体 + 流转记录）：**

1. 单据始终为同一条记录；转包 = 变更负责人 + 写流转记录（操作人/时间/转出人 → 转入人/备注必填）
2. 流转记录页展示完整链条：创建 → 转包 1 → 转包 2 ...
3. 转包后原负责人立即失去编辑权；字段内容全部随单继承

**通知：** 创建 → 通知负责人；转包 → 通知新负责人；状态变更 → 通知创建者。

**验收标准：**

- 测试员角色无创建需求单入口

- 转包后新负责人获得编辑权、旧负责人只读；流转链完整可见

- 已取消/已完成单据任何入口均只读

#### F10 bug 单

**权限模型：** 所有角色均可创建；创建必填标题、bug 操作明细、bug 界面截图、负责人（必填），创建即开发中。

| 角色               | 可编辑内容                                                 |
| :----------------- | :--------------------------------------------------------- |
| 创建者（始终不变） | 标题、操作明细、界面截图、重新指定负责人（=转包）          |
| 当前负责人         | bug 原因、解决方案、结果截图、状态（开发中/已完成/已取消） |

- 转包后旧负责人立即失权；转包必须填备注，入流转记录；
- 已完成/已取消只读；单据不可删除；
- 通知：创建→负责人；转包→新负责人；状态变更→创建者。

**验收标准：**

- 未指定负责人无法提交 bug 单

- 创建者与当前负责人的编辑边界与上表完全一致，越权请求被接口拒绝

- 转包两次后，流转记录完整显示 创建→转包 1→转包 2 及各自备注

#### F11 任务变更通知

**功能描述：** 复用聊天 STOMP 通道，以系统消息推送给相关人。系统消息采用广播方式（`/queue/system`）推送，所有在线用户均收到，前端按 receiverId 过滤出属于自己的通知并弹提示（未命中则不展示）。通知矩阵：

| 事件          | 接收人                       |
| :------------ | :--------------------------- |
| 单据创建      | 负责人                       |
| 转包          | 新负责人                     |
| 状态变更      | 创建者                       |
| 版本关闭/取消 | 该版本下所有未完结单据负责人 |

任务页 30s 轮询兜底（防推送丢失）；不做声音提醒；标题闪烁为可设置项（默认开启闪烁、关闭声音）。

**验收标准：**

- 上表四类事件实时推送到位（离线者上线补拉）；推送丢失时轮询在 30s 内补齐列表状态

#### F12 账号管理后台

**功能描述：** 同 jar 部署、独立路径入口（如 `/admin.html`），独立 admin 账号（账号密码配置于 `application.yml`，无首次强制改密），与注册用户体系完全隔离。仅三项能力：

1. **账号查询：** 按手机号/姓名/工号查询账号列表；
2. **重置密码：** 一键重置为 123456，按注册同款加密口径入库；不强制用户下次改密、不发送任何系统消息通知；
3. **删除账号：** 逻辑删除 -- 登录失效、好友列表消失、历史消息/单据保留原姓名快照；后台可恢复；手机号可重新注册为全新账号（旧数据不可见不迁移）。

**边界条件：** admin 账号不出现在任何用户列表中；admin 密码错误提示与普通登录一致处理。

**验收标准：**

- 普通用户 session 访问后台接口一律 401/403

- 重置密码后旧密码即刻失效、123456 可登录；用户侧无任何通知消息

- 删除账号后：该号登录被拒、从他人好友列表消失、历史消息显示姓名快照；重新注册为独立新账号

#### F13 断线重连与离线禁发（错误处理总则）

- WebSocket 断线：自动重连（间隔 3s，不设上限），重连期间顶部黄色横幅提示；
- 离线禁发：断线期间输入框与发送/上传入口置灰，提示“连接已断开”；不做本地消息队列（避免乱序）；
- 接口错误：统一 toast 提示后端错误信息；文件/图片上传失败：消息保持本地失败态气泡，支持点击重试（详见 F04 上传时序模型）；
- 登录态过期：任意请求 401 → 重定向登录页。

**验收标准：**

- 人为断开服务再恢复：客户端自动重连成功、横幅消失、离线期间消息经补拉
